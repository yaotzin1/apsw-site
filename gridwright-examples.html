ARCHITECTURAL GUARDRAILS

Strict Agent Rules: Always vs Never

AI coding agents writing apsw-gridwright code MUST follow these foundational rules without deviation.

✔ Always
MANDATORY
  • ✓ Give every grid an aria-label or a caption for accessibility.
  • ✓ Build a data source in useMemo (deps = what it reads) or at module scope. Never inline in JSX.
  • ✓ Declare capabilities truthfully. Unstated facets default to all-true for remote sources.
  • ✓ Use formatValue when the cell's answer is text; cell only for real React nodes.
  • ✓ Pass signal from the fetcher directly into fetch for cancellation.
  • ✓ Pass getRowId whenever row records do not have an id property.
  • ✓ Put features in addons={[...]}; put per-column configuration directly on the column definition.
  • ✓ Keep virtualRows({ rowHeight }) strictly equal to the CSS property --gw-row-height.
  • ✓ Let inlineEditing's commit throw an Error to reject an edit. Do not mutate local state manually.
✖ Never
FORBIDDEN
  • ✗ Never compute or fake a total the source did not supply. No totalRows means the grid says "of many", and that is correct.
  • ✗ Never claim a capability the backend endpoint does not implement.
  • ✗ Never list rowDetail() together with virtualRows() — it throws by design.
  • ✗ Never give an add-on's extra <tr> role="row"; use role="presentation" with a labelled role="region" inside.
  • ✗ Never assert on class names or DOM structure in tests. Query strictly by ARIA role and accessible name.
  • ✗ Never add a runtime dependency to make a recipe or feature work.
  • ✗ Never render a visible string as a JSX literal inside an add-on; use messages / labels.
  • ✗ Never reach into the grid's DOM to attach behaviour. Use the formal add-on contract.

PLAYBOOK RECIPES

Canonical Code Snippets Library

Zero-narrative, battle-tested code snippets directly from the agent playbook. Click any copy button to drop directly into your application.

1. Standard Package Imports

Entry imports and module boundaries. Peer dependencies: React 18 or 19. Zero runtime dependencies.

import { Gridwright, /* add-ons, hooks, parts */ } from 'apsw-gridwright/react'; // build with this
import { createRestDataSource, /* engine, sources */ } from 'apsw-gridwright';   // headless engine
import { pl } from 'apsw-gridwright/locales';                                    // translations
import 'apsw-gridwright/styles.css';                                             // once, at the entry

2. Grid over an Array

Simple typed columns over in-memory client data. Always declare formatValue for text.

const columns: GridwrightColumn<Person>[] = [
    { id: 'name', header: 'Name' },
    { id: 'salary', header: 'Salary', align: 'end', formatValue: (v) => money.format(Number(v)) },
];

<Gridwright<Person> columns={columns} data={people} pageSize={25} aria-label="People" />;

3. Grid over REST (Wire Format)

Connected to backend endpoints like /api/people. Data source must be built in useMemo.

const source = useMemo(() => createRestDataSource<Person>({ url: '/api/people' }), []);

<Gridwright<Person> columns={columns} dataSource={source} pageSize={25} aria-label="People" addons={[search()]} />;
Wire format sent: page (one-based), pageSize, sort=col:asc,other:desc, search, filters (JSON array of { columnId, operator, value }).
Accepted back: an array, { data, total }, { items, count }, meta.total, or an X-Total-Count header. Override with buildParams / parseResponse.

4. Grid over Async (GraphQL / SDK / tRPC)

Custom async fetcher with declared capabilities and abort signal forwarding.

const source = useMemo(
    () =>
        createRemoteDataSource<Person>({
            capabilities: { paginate: true, sort: false, filter: false, search: false },
            fetcher: async ({ query, signal }) => {
                const { pageIndex, pageSize } = query.pagination;
                const body = await client.people.list({ page: pageIndex + 1, size: pageSize }, { signal });
                return body.total === undefined ? { rows: body.rows } : { rows: body.rows, totalRows: body.total };
            },
        }),
    [client],
);

5. Add-ons Ecosystem & Core Add-ons

Configuring add-ons. Core four (sorting, selection, pagination, staleNotice) are on by default.

// Explicit feature add-ons
addons={[search(), columnFilters(), exportMenu({ filename: 'people' }), rowActions({ items })]}

// Configuring default core add-ons
coreAddons={coreAddons<Person>({
    selection: { checkboxes: false },
    pagination: { pageSizeOptions: [10, 50] }
})}

// Or remove all core add-ons:
coreAddons={false}
Changing which add-on names are listed remounts the grid. This is by design; it resets the page.

6. Selection & Engine State

Selection is engine state. Provide getRowId when rows lack a default id property.

<Gridwright<Person>
    selectionMode="multiple"
    onSelectionChange={(ids, rows) => setSelected(rows)}
    getRowId={(row) => row.uuid}
/>

7. Editable Cells & Inline Commit (with Throw Revert)

Throwing an error in commit rejects the edit and reverts the cell automatically.

// 1. Column Definition
{ id: 'salary', header: 'Salary', edit: { inputType: 'number', editable: (row) => row.canEditPay } }

// 2. Add-on Configuration
inlineEditing({
    commit: async (rowId, columnId, value) => {
        const response = await fetch(`/api/people/${rowId}`, {
            method: 'PATCH',
            headers: { 'Content-Type': 'application/json' },
            body: JSON.stringify({ [columnId]: value }),
        });
        if (!response.ok) throw new Error(await response.text()); // throwing reverts the cell!
        source.invalidate();
    },
})

8. Expandable Rows / Master–Detail

Render runs only while open; unmounted collapsed panels provide automatic lazy loading.

rowDetail<Order>({
    hasDetail: (row) => row.data.lineCount > 0,
    render: ({ data, close }) => <OrderLines orderId={data.id} />,
})

9. Huge Datasets (Windowed Data Source + Virtual Rows)

Combines block windowing with DOM row virtualization. Total rows is required here.

const source = useMemo(
    () =>
        createWindowedDataSource<Person>({
            blockSize: 200,
            maxBlocks: 12,
            fetchRange: async ({ offset, limit, query, signal }) => {
                const body = await api.people({ offset, limit }, { signal });
                return { rows: body.rows, totalRows: body.total }; // totalRows is REQUIRED here
            },
        }),
    [api],
);

<Gridwright<Person> columns={columns} dataSource={source} pageSize={100} aria-label="People" addons={[virtualRows({ rowHeight: 40, height: 600 })]} />;

10. Persisting State & URL Sync

Preserves queries, widths, pinning, and expanded panels without overwriting on mount.

initialQuery={saved}                                            // read once, at engine creation
onQueryChange={(q) => save(q)}                                  // sort, filters, search, page
columnLayout({ initial, onChange })                             // widths, pinning, visibility, order
rowDetail({ initialExpanded, onExpandedChange })                // open panels

11. Custom Add-on Architecture

Strict allowlist attributes and presentational row expansion. Zero direct DOM reaching.

const highlight = (): GridAddon<Row> => ({
    name: 'acme:highlight',                    // namespaced; also the messages namespace
    setup: function useHighlight() {           // may call hooks; name it use* for lint
        return {
            cellAttributes: (row, column) => (column.id === 'due' && row.data.overdue ? { className: 'is-overdue' } : {}),
            toolbar: () => <MyButton />,       // slot functions must NOT call hooks
            messages: { en: { label: 'Overdue' } },
        };
    },
});

12. Accessible Testing Patterns

Query strictly by WAI-ARIA role and name. No arbitrary sleep timers or class-name queries.

screen.getAllByRole('row')                                   // [0] is the header
within(row).getAllByRole('cell')
screen.getByRole('button', { name: /Salary/ })               // the sort control
screen.getByRole('columnheader', { name: /Salary/ })         // carries aria-sort
screen.getByRole('status')                                   // the live region
screen.getAllByRole('checkbox', { name: 'Select row' })
await waitFor(() => expect(screen.getAllByRole('row')).toHaveLength(1 + 25));  // no arbitrary timers

13. Theming & Translations

Override custom properties on any ancestor without forking styles. First-class i18n locales.

/* CSS custom property tokens: */
--gw-font-size, --gw-line-height, --gw-row-height, --gw-cell-padding-x,
--gw-cell-padding-y, --gw-radius, --gw-gap, --gw-surface, --gw-surface-muted,
--gw-surface-hover, --gw-surface-selected, --gw-text, --gw-text-muted, --gw-border,
--gw-border-strong, --gw-accent, --gw-accent-contrast, --gw-danger, --gw-focus-ring.

// JSX Localization:
<Gridwright locale={pl} /* or */ translate={(key, values) => t(key, values)} /* or */ messages={{ 'status.empty': 'Brak danych' }} />
CI VERIFICATION GATES

AI Agent Pre-Flight Audit Checklist

AI coding agents and reviewers must execute this verification checklist before reporting any task complete.

Audit Check Failure Consequence (Why It Fails CI)
Is every data source inside useMemo or at module scope? An inline data source recreates on every paint and refetches indefinitely.
Do capabilities match what the endpoint implements? Silent no-op sorting and filtering on the server.
Does every grid have an aria-label or caption? Screen readers announce only an anonymous "table".
Is apsw-gridwright/styles.css imported once at entry? Grid renders completely unstyled with zero layout rules.
Do rows have stable IDs (or a custom getRowId)? Selection state and expandable panels lose their keys across updates.
Does virtualRows({ rowHeight }) match --gw-row-height? Rendered rows drift away from the scrollbar during fast scrolling.
Is any total count being computed client-side? Strict violation. Never compute or fake totals not provided by the source.
Are automated tests querying by role rather than class names? Class names are internal styles, not public architectural contracts.
ENGINEERING PROTOCOL

Escalate to User, Do Not Guess

Definitive boundaries where an autonomous AI agent must pause and ask the human architect instead of making assumptions.

⚠ Unknown Endpoint Paging Contract

If the endpoint's paging contract is unknown (zero- vs one-based, custom parameter names like offset vs page), pause and confirm with the user rather than guessing wire formats.

⚠ Unavailable Total Row Count

If the endpoint cannot return a total and the user asked for an exact page count, inform them that the grid will say "of many", and why. Never fake client-side totals.

⚠ Deliberately Closed Features

If a requirement demands a feature the package refuses on purpose (e.g. expandable rows combined with windowing, external runtime dependencies), name the architectural refusal and offer the nearest clean alternative.

⚠ Missing Add-on Extension Seam

If a required seam does not exist in the add-on contract, that is a gap in the package. Never reach into the grid's internal DOM.
